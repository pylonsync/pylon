## What is Pylon?

Pylon is a full-stack framework built for coding agents. You or your agent write the schema, policies, and functions in TypeScript. Pylon runs the backend and React SSR on Bun behind one Rust server, generates a typed client, and keeps shared state in sync for dashboards, CRMs, collaborative tools, and chat.

The same server handles the database, API, auth, and WebSocket connections. It runs on SQLite or Postgres and deploys with one command.

## What you get

- **Typed schema:** declare entities in TypeScript and get types everywhere.
- **Row-level policies:** keep access rules next to your data instead of in middleware.
- **Server functions:** call queries, mutations, and actions from the client over RPC.
- **Live queries:** `db.useQuery(...)` subscribes to results and updates after writes.
- **Auth:** email magic links, OAuth, and guest sessions without a third-party SDK.
- **SSR:** file-based React routes with [`<Link>`](/ssr/link), [`<Image>`](/ssr/image), and built-in [Tailwind](/ssr/styling), without Next.js.
- **One server:** a Rust binary that runs your TypeScript and SSR on Bun, on one port.

## One backend runtime

Most realtime backends are three systems glued together: a database, an API server, and a realtime pub/sub layer. Keeping them in sync is a full-time job.

Pylon puts those jobs in one runtime. Writes go through the same process that serves reads and pushes updates. Live queries re-execute when dependent rows change and stream diffs to subscribers, without a separate cache-invalidation or fan-out layer.

## What it's good for

- SaaS apps with live dashboards
- Internal tools, CRMs, ERPs
- Collaborative editors
- Multiplayer games and worlds
- Anything where two browsers need to see the same thing, now

## Storage

Pylon runs on SQLite or Postgres. SQLite is the zero-setup default for local development and single-node production workloads up to tens of gigabytes. Switch to Postgres for horizontal scale, existing Postgres infrastructure, or shared-nothing deployments. The schema, policies, functions, and client APIs stay the same; set `DATABASE_URL=postgres://...` to use the Postgres adapter.
